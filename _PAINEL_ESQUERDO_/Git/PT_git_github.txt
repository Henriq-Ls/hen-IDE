## 2.2 Remote "origin" não é restaurado ao reabrir projeto já publicado

ARQUIVO: _PAINEL_ESQUERDO_/Git/git_ui.py  +  git_gerente.py

COMPORTAMENTO ESPERADO:
  Ao abrir um projeto que já foi publicado no GitHub pela hein IDE,
  o remote "origin" é verificado. Se estiver ausente mas o projeto
  constar em projetos_recentes (github_config.json com URL salva),
  o remote é reconfigurado automaticamente.

COMPORTAMENTO ATUAL (BUG DE LÓGICA):
  set_projeto() verifica apenas se .git existe (tem_git()).
  Se yes → vai para Tela 3.
  O git remote pode estar vazio. Ninguém verifica.
  Push falha com "origin does not appear to be a git repository".
  O usuário não tem como saber o que aconteceu nem como resolver.

CAUSA RAIZ:
  git_ui.py:set_projeto() — chama git.tem_git() e vai direto para
  _tela_projeto.abrir_projeto(caminho). Nunca consulta
  config_github().projetos_recentes para restaurar o remote.
  git_gerente.py:definir_remoto() existe e funciona, mas não é chamado
  nesse fluxo.

ONDE IMPLEMENTAR:
  git_ui.py — set_projeto() e _ir_para_projeto():
    Após confirmar que tem .git, verificar git remote -v.
    Se vazio, buscar caminho em config_github().projetos_recentes.
    Se encontrar URL salva → chamar git.definir_remoto() em thread
    e exibir no terminal: "Repositório reconectado ao GitHub."
    Se não encontrar → exibir estado "sem repositório remoto" (ver 3.6).

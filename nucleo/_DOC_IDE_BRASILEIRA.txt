VISÃO GERAL
───────────
A hein IDE foi concebida para ser a primeira IDE desktop verdadeiramente
brasileira: interface, mensagens de erro, temas, correção ortográfica e
documentação inteiramente em português do Brasil.

Este documento registra todos os módulos, decisões de arquitetura e regras
que sustentam essa identidade.

1. TRADUTOR DE ERROS DO PYTHON
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Módulo: _TRADUTION_/tradutor_erros.py

O que faz:
  Intercepta as mensagens de erro padrão do Python (em inglês) e as converte
  para português claro e didático, acessível a quem está aprendendo.

  Exemplos de tradução:
    "SyntaxError: invalid syntax"          → "Erro de sintaxe: sintaxe inválida"
    "NameError: name 'x' is not defined"   → "Erro de nome: 'x' não foi definido"
    "IndentationError: unexpected indent"  → "Erro de indentação: recuo inesperado"
    "TypeError: unsupported operand type"  → "Erro de tipo: operação não suportada"
    "ZeroDivisionError: division by zero"  → "Erro: divisão por zero"

Onde é usado:
  - _EDITOR_/Outline (status bar) — traduz erros de parse exibidos abaixo do outline
  - Terminal Run (futuro) — traduz exceções em runtime antes de mostrar ao usuário

Regras de manutenção:
  - Toda nova mensagem de erro do Python que aparecer na hein deve ser mapeada aqui
  - Nunca traduzir nomes de variáveis/funções do código do usuário, apenas as
    mensagens fixas do interpretador
  - O módulo é estático — sem estado, sem QThread, sem dependências de UI

2. CORRETOR ORTOGRÁFICO PT-BR
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Módulo principal: _EDITOR_/Funcionalidades/corretor_ortografico.py

2.1 VISÃO GERAL
───────────────
O corretor ortográfico verifica a escrita em português em:
  - Strings e comentários de arquivos Python
  - Texto completo de arquivos .txt, .log, .csv, .ini, .cfg, .toml
  - Texto principal de arquivos Markdown (.md), excluindo blocos de código

O que NÃO é corrigido (intencional):
  - Nomes de variáveis, funções, classes, módulos
  - Nomes de arquivos e caminhos
  - Código dentro de blocos ``` em Markdown
  - Código inline com ` em Markdown
  - URLs (https://...)
  - Palavras com menos de 3 letras (false positives de artigos e preposições)

2.2 ARQUITETURA — DOIS NÍVEIS
──────────────────────────────

Nível 1 — Básico (sempre disponível, bundlado no .exe):
  Arquivo:   AppData\hein\dicionarios\pt_BR_basico.txt
  Origem:    _APPDATA_/dicionarios/pt_BR_basico.txt (copiado no primeiro uso)
  Conteúdo:  ~3.000 palavras mais comuns do PT-BR
             (verbos, substantivos, adjetivos, termos de programação)
  Motor:     Levenshtein puro Python (stdlib) — zero dependências externas

Nível 2 — Completo (opcional, download sob demanda):
  Arquivo:   AppData\hein\dicionarios\pt_BR_completo.txt  [FUTURO]
  Origem:    Download via _venv_hein_ / VenvHeinManager
  Conteúdo:  ~200.000 palavras (Hunspell PT-BR convertido para .txt)
  Motor:     Mesmo Levenshtein — só o dicionário muda
  Ativação:  Automática — se o arquivo existir, é carregado junto com o básico

Dicionário do usuário (sempre disponível, persiste entre sessões):
  Arquivo:   AppData\hein\dicionarios\pt_BR_usuario.txt
  Origem:    Criado pela hein quando o usuário clica "+ Adicionar ao dicionário"
  Conteúdo:  Palavras pessoais — nomes próprios, termos técnicos, jargões
  Hot-reload: Automático via invalidar_dicionario() após cada adição

2.3 FLUXO DE VERIFICAÇÃO
─────────────────────────

  Usuário digita
        │
        ▼
  textChanged → debounce 1200ms → _lancar_correcao()
        │
        ▼
  _ThreadCorretor.run() [background — nunca bloqueia UI]
        │
        ├── modo "python"   → _extrair_python()
        │                      tokenize.generate_tokens() → STRING + COMMENT
        │                      Pula variáveis, defs, classes
        │
        ├── modo "texto"    → _extrair_texto()
        │                      regex palavra por palavra, linha por linha
        │
        └── modo "markdown" → _extrair_markdown()
                               Pula blocos ```, código inline `, URLs
        │
        ▼
  Para cada palavra extraída: _esta_correto(palavra)?
        │
        ├── Sim → ignora
        └── Não → adiciona à lista de erros (linha, col_ini, col_fim, palavra)
        │
        ▼
  concluido.emit(erros) → UI thread
        │
        ▼
  _construir_selecoes() → QTextCharFormat.SpellCheckUnderline (amarelo-dourado)
        │
        ▼
  _aplicar_selecoes() → setExtraSelections()
  [mescla com import validator e lint — não sobrescreve]

2.4 POPUP DE SUGESTÕES
───────────────────────

  Ativação: hover do mouse sobre palavra sublinhada
  Padrão:   Qt.ToolTip + FramelessWindowHint + WA_ShowWithoutActivating
            (mesmo padrão do _PopupDiffHunk da calha git)

  Conteúdo do popup:
    - Nome da palavra marcada (amarelo)
    - Até 5 sugestões clicáveis (distância de Levenshtein ≤ 2)
    - "+ Adicionar ao dicionário" → grava em pt_BR_usuario.txt

  Algoritmo de sugestão:
    1. Filtra candidatos: mesma inicial + comprimento ±2
    2. Fallback: comprimento ±1 (sem restrição de inicial)
    3. Calcula distância de Levenshtein para cada candidato
    4. Retorna os 5 com menor distância (≤ 2)

2.5 INTEGRAÇÃO COM O EDITOR
─────────────────────────────

Ponto de integração: Editor/__init__.py (CodeEditor)

O corretor é instanciado com base no atributo spell_check do LanguageProvider:

  provider = get_provider(extensao)
  if provider.spell_check:
      modo = "python" if extensao in ('.py', '.pyw') else "texto"
      if extensao in ('.md', '.markdown'):
          modo = "markdown"
      self._corretor = CorretorOrtografico(self, modo)
      self._corretor.verificar_agora()
  else:
      self._corretor = None

Providers com spell_check = True:
  ✅ Python/    (.py, .pyw)   → modo "python"   (strings + comentários)
  ✅ Texto/     (.txt, .log,  → modo "texto"    (texto puro completo)
                 .csv, .ini,
                 .cfg, .toml)
  ✅ Markdown/  (.md, .md)    → modo "markdown" (texto excluindo blocos de código)

Providers com spell_check = False (intencional):
  ✗  JSON, XML, YAML, HTML, JavaScript, Shell, SQL, C/C++, Makefile, Lua,
     Dockerfile — são formatos de código ou marcação estruturada, não texto livre

2.7 REGRAS DE MANUTENÇÃO
──────────────────────────

  RB-01  O corretor NUNCA verifica identificadores Python (variáveis, funções,
         classes). Apenas o conteúdo semântico de strings e comentários.

  RB-02  RG-02 se aplica: _ThreadCorretor roda em QThread — NUNCA na UI thread.

  RB-03  O dicionário é carregado lazy (na primeira verificação) e cacheado em
         memória (_dicionario: set[str]). invalidar_dicionario() limpa o cache.

  RB-04  Ao adicionar palavra ao dicionário do usuário, sempre chamar
         invalidar_dicionario() logo após a escrita no arquivo.

  RB-05  setExtraSelections() do corretor NUNCA sobrescreve as seleções de
         outros sistemas (import validator, lint, busca). Sempre mescla.

  RB-06  A cor do sublinhado ortográfico é #e5c07b (amarelo-dourado).
         Não alterar — serve para distinguir de erros de import (vermelho)
         e lint (também vermelho/laranja).

  RB-07  Palavras com menos de 3 caracteres não são verificadas (regex {3,}).

  RB-08  O dicionário pt_BR_basico.txt é a fonte de fábrica — nunca modificar
         em runtime. Customizações do usuário vão sempre em pt_BR_usuario.txt.

  RB-09  Palavras são comparadas em lowercase. O dicionário deve conter apenas
         palavras em minúsculas.

    cafe_com_leite   — bege caramelo, quente e acolhedor

  - Usar tema_global().dados() nas cores — nunca hex hardcoded nos widgets

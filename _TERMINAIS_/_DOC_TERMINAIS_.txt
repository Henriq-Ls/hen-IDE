# OBJETIVO
Prover os terminais integrados da IDE e dois grupos de painéis visuais:
  (1) Terminais de execução — Run (código do usuário na venv), PowerShell
      interativo, e Depurador (sessão DAP via debugpy).
  (2) Explorers de configuração — um painel visual dedicado para cada
      arquivo JSON de configuração da IDE (_CONFIGURA_/). O usuário
      edita cores, atalhos, fontes, snippets e parâmetros do Núcleo
      sem precisar tocar no JSON cru.

─────────────────────────────────────────────────────────────────
# RESPONSABILIDADES
─────────────────────────────────────────────────────────────────

TERMINAIS:
- Executar o código do usuário na venv do projeto (terminal Run)
- Imprimir output em tempo real sem bloquear a UI
- Detectar automaticamente JSON/dict no output do terminal Run
- Exibir barra de notificação quando JSON é detectado
- Prover aba visual { } JSON com árvore colapsável e código gerado
- Gerar código Python pronto para acessar cada chave do JSON
- Copiar caminhos de chaves e código para área de transferência
- Abrir código gerado como nova aba no editor
- Prover botão { } de acesso ao JSON Explorer em todos os terminais
- Iniciar sessão de depuração real com debugpy via protocolo DAP
- Controlar fluxo do depurador: Continuar, Próxima Linha, Entrar, Sair, Parar
- Exibir variáveis locais do frame atual em tempo real
- Encerrar o processo debugpy e liberar recursos ao fechar a aba

EXPLORERS DE CONFIGURAÇÃO:
- Exibir painel visual ao abrir qualquer JSON de _CONFIGURA_ no editor
- Cada Explorer é roteado automaticamente por _ao_trocar_aba_editor_json()
- Permitir edição com controles adaptados (swatch de cor, SpinBox, ComboBox etc.)
- Salvar via json.dump e disparar hot-reload sem reiniciar a IDE
- Sincronizar bidireccionalmente com QFileSystemWatcher: se o JSON mudar
  no disco (edição manual), o Explorer recarrega automaticamente

── ExecutavelExplorer ─────────────────────────────────────────────

  _TERMINAIS_/executavel_explorer.py
    ExecutavelExplorer(QWidget) — editor tipado bidirecional do executavel.json.
    Abre automaticamente via _ao_trocar_aba_editor_json() ao abrir executavel.json
    no editor (Ctrl+9 / botões do PainelExecutavel).
    Layout 3 painéis: QSplitter vertical (conteúdo [400px] + terminal build [150px])
    + QSplitter horizontal interno (coluna esquerda [200px] + formulário [500px]).
    Coluna esquerda: _txt_requirements (deps lidas de requirements.txt) +
    _txt_arvore (lida de arvore.txt) — ambos em .hein/executavel/.
    _ler_gitignore(raiz): parseia .gitignore e retorna set[str] de padrões simples.
    _auto_detectar(): gera árvore, pip freeze e análise local; grava os campos
    detectados em .hein/executavel/executavel.json.
    _recarregar_se_necessario(): padrão dos outros Explorers (mtime).

    _iniciar_release() / _ao_release_concluido() — release pelo GitHub Actions:
      1. Gera .github/workflows/release-executavel.yml e um build_ci.py
         autônomo dentro de .hein/executavel/ do projeto do usuário.
      2. Inclui workflow, requirements.txt e configuração usando git add -f,
         sem adicionar arquivos não relacionados que já estejam staged.
      3. Usa config_github() e GerenciadorGit.executar_autenticado(); a
         credencial fica no helper temporário, não na URL ou nos argumentos.
      4. Recusa tag remota já publicada e tag local em outro commit; não usa
         tag -f nem force-push. Falha entre push de branch/tag pode ser retomada
         somente quando a tag local aponta para o HEAD atual e os arquivos estão iguais.
      5. GitHub Actions instala requirements.txt, roda PyInstaller no Windows,
         empacota onedir em ZIP e publica o artefato com contents: write.

    Build local:
      1. Usa a .venv do projeto ativo, instala PyInstaller nela e não depende
         de conta ou conexão GitHub.
      2. GerarSpecThread cria spec/version resource; ProcessoThread executa
         PyInstaller sem abrir console auxiliar.

      _listar_arquivos_cwd(): Tab cicla arquivos/pastas do cwd; detecta

  _TERMINAIS_/Debug/cliente_dap.py
    ClienteDAP(QThread) — cliente DAP completo para debugpy.
    Construtor: __init__(arquivo, python_path, porta=0)
      porta=0 → chama _porta_livre() para porta TCP efêmera.

    Sinais emitidos (thread-safe via Qt):
      pausado(arquivo: str, linha: int)
      variaveis_recebidas(list[dict])   — dicts {nome, tipo, valor}
      executando()
      encerrado()
      erro(str)

    API pública (chamável da thread principal):
      continuar()          → DAP continue
      proximo()            → DAP next
      entrar()             → DAP stepIn
      sair()               → DAP stepOut
      parar()              → DAP disconnect + _encerrar()
      set_breakpoints(linhas: list[int]) → DAP setBreakpoints

    Métodos internos:
      _porta_livre()           socket bind("",0) → porta efêmera
      _iniciar_processo()      subprocess.Popen com CREATE_NO_WINDOW (Win);
                               adiciona --stop-on-entry na linha de comando
                               quando não há breakpoints definidos
      _conectar_socket()       tenta conexão TCP por até 15s
      _handshake()             initialize → aguarda response →
                               attach → aguarda initialized event →
                               setBreakpoints → configurationDone
                               (stopOnEntry no corpo do attach é ignorado
                               pelo debugpy em modo --listen)
      _loop_mensagens()        despacha stopped/continued/exited
      _encerrar()              terminate/kill processo → drena stderr →
                               fecha socket (ordem correta evita deadlock)

    Constantes:
      _HOST            = "127.0.0.1"
      _TIMEOUT_CONEXAO = 15  (segundos para o debugpy subir)
      _TIMEOUT_RECV    = 1.0 (timeout de recv — permite verificar _parar)

    Segurança de thread:
      _seq_lock (threading.Lock) — protege _seq e socket.sendall()
      _parar (bool) — flag de encerramento verificada em todo loop

# FLUXO DOS EXPLORERS DE CONFIGURAÇÃO
─────────────────────────────────────────────────────────────────

ABERTURA AUTOMÁTICA:
  1. Usuário pressiona Ctrl+N (ex: Ctrl+3 → thema.json)
  2. main_window chama add_new_tab(ARQUIVO_*) → JSON cru no editor
  3. _ao_trocar_aba_editor_json() detecta o caminho do arquivo
  4. Instancia o Explorer correspondente (ThemaExplorer, etc.)
  5. Adiciona em nova aba do terminal_tabs com ícone e nome do JSON
  6. Se a aba já existia, apenas foca nela + _recarregar_se_necessario()

EDIÇÃO E SALVAMENTO:
  1. Usuário edita campos visuais (hex, SpinBox, ComboBox, etc.)
  2. Clica "Salvar" no cabeçalho do Explorer
  3. Explorer chama json.dump → grava arquivo JSON
  4. QFileSystemWatcher do gerenciador detecta a mudança
  5. Hot-reload aplica as novas configurações em toda a IDE

SINCRONIZAÇÃO BIDIRECIONAL:
  - QFileSystemWatcher no Explorer monitora o arquivo
  - Se o JSON for editado externamente (ex: outro editor), o Explorer
    recarrega automaticamente via _ao_arquivo_mudar()
  - _recarregar_se_necessario() compara mtime antes de reconstruir o UI

─────────────────────────────────────────────────────────────────
# FLUXO DOS TERMINAIS DE EXECUÇÃO
─────────────────────────────────────────────────────────────────

DETECÇÃO AUTOMÁTICA DE JSON:
  1. Usuário roda código → output impresso no terminal Run
  2. _imprimir() agenda _verificar_json() via QTimer.singleShot(0)
  3. Se JSON encontrado e diferente do anterior → exibe _barra_json

SESSÃO DE DEPURAÇÃO:
  1. Botão 🐛 → debug_solicitado → main_window._iniciar_debug()
  2. main_window coleta BPs do NumeroLinhas do editor ativo
  3. terminal_tabs.abrir_aba_debug(arquivo) → PainelDebug
  4. PainelDebug.iniciar_sessao(arquivo, python_path, breakpoints)
     → cria ClienteDAP → start()
  5. ClienteDAP: Popen (com --stop-on-entry se sem BPs) → TCP →
     handshake DAP → setBreakpoints → loop de eventos
  6. Botões do painel controlam o fluxo (next/step/continue/stop)

SINCRONIZAÇÃO DE BREAKPOINTS EM TEMPO REAL:
  - NumeroLinhas.breakpoint_clicado → _ao_breakpoint_clicado(linha)
  - _ao_breakpoint_clicado() verifica: arquivo do editor == arquivo
    da sessão ativa; se diferente, descarta (guard de arquivo)
  - Chama painel_debug_ativo().sincronizar_breakpoints(BPs_atuais)
  - sincronizar_breakpoints() delega para ClienteDAP.set_breakpoints()
  - _ao_trocar_aba_breakpoint() reconecta o sinal ao NumeroLinhas
    correto quando o usuário muda de aba no editor

  debugpy (instalado na venv do projeto do usuário)
    Biblioteca de terceiros. Não deve estar na venv da IDE.

# REGRAS
─────────────────────────────────────────────────────────────────

EXPLORERS:
- Cada Explorer monitora seu próprio JSON com QFileSystemWatcher
- _recarregar_se_necessario() compara mtime — não reconstrói se igual
- Import dos Explorers é lazy (dentro de _ao_trocar_aba_editor_json)
  para evitar import circular na inicialização
- Aba de Explorer é reutilizada — nunca duplica
- Salvar no Explorer → json.dump → remove comentários // do JSON.
  Esperado: os labels do Explorer substituem os comentários.
- ThemaExplorer: cor HexArgb (#aarrggbb) usada quando alpha < 255

TERMINAIS:
- _verificar_json() roda via QTimer.singleShot(0) — nunca bloqueia
- Aba { } JSON NÃO entra em self.terminais (painel visual puro)
- Aba { } JSON e aba "Depurador" são reutilizadas — sem duplicata
- Limite de 50 itens em listas (evita travar com JSON grande)
- ClienteDAP usa stdout=DEVNULL — nunca stdout=PIPE
- _parar_sessao_atual() DEVE ser chamado antes de removeTab() com PainelDebug
- debugpy deve estar na venv do projeto, não na venv da IDE

debugpy — modo de operação:
  Modo --listen --wait-for-client → comando DAP é attach (não launch).
  stopOnEntry no corpo do attach é ignorado pelo debugpy em modo --listen.
  Para pausar na linha 1 sem BPs: passar --stop-on-entry na linha de
  comando do subprocess (não como parâmetro DAP).

Variáveis filtradas no depurador:
  Nomes com prefixo __ ou @py_ são excluídos (internas do Python/debugpy).

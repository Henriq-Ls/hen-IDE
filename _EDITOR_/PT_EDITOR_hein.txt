FORMATO DO ARQUIVO .hein
─────────────────────────
  Texto puro (UTF-8), estruturado por marcadores de cabeçalho Markdown-like:

  # Nome da nota           ← bloco 0: H1, título (sem número de linha)
  20 — julho               ← bloco 1: data (sem número de linha)
                           ← bloco 2+: conteúdo livre, com números de linha
  ## pasta/                ← pasta do projeto
      ### arquivo.py       ← arquivo do projeto
          conteúdo...

  O cabeçalho (blocos 0 e 1) é gerado automaticamente na criação.
  A estrutura H2/H3 é sincronizada com o projeto via sincronizar_estrutura().

COMO AS CORES FUNCIONAM (crítico — ler antes de mexer)
──────────────────────────────────────────────────────
  O tema da IDE é escuro. O caderno precisa ser sempre claro. Para vencer o
  tema, _aplicar_fundo() usa 4 camadas empilhadas:

  CAMADA 1 — document().rootFrame().setFrameFormat(ff) com ff.setBackground(cor)
    → Preenche as áreas de margem do QTextDocument (espaço entre blocos,
      padding de QTextBlockFormat). Sem isso, qualquer bloco com topMargin
      ou bottomMargin aparece com fundo preto herdado do tema da IDE.

  CAMADA 2 — document().setDefaultCharFormat(char_fmt) com setForeground(cor)
    → Define a cor de texto para caracteres SEM formato explícito do
      highlighter. É ESTE canal que o renderer Qt usa para texto normal.
      QPalette.Text não é suficiente para isso.

  CAMADA 3 — viewport().setStyleSheet("background-color: ...; color: ...;")
    → Vence qualquer stylesheet pai herdada da IDE. CSS tem prioridade
      sobre QPalette quando há stylesheet no widget.

  CAMADA 4 — viewport().setPalette(pal) + setAutoFillBackground(True)
    → Fallback para seleção de texto, scrollbar, highlight de seleção.

  O _GutterHein vence o tema escuro por paintEvent:
    painter.fillRect(event.rect(), self._cor_fundo)
  Essa linha preenche o gutter antes de qualquer outro desenho.

  aplicar_tema() ignora completamente o dicionário de tema da IDE.
  Só aceita chaves com prefixo "caderno_" (ex: "caderno_fundo").
  Nenhum tema atual tem essas chaves, então o caderno sempre inicia
  com as cores padrão (#FDFBF7 fundo, #1A1A1A texto, #E0DCD3 pautas).

## 1.1  _BarraSalto — posicionamento não acompanha resize do editor

ARQUIVO: _EDITOR_/Editor/_barra_salto.py
         _EDITOR_/Editor/__init__.py

COMPORTAMENTO ESPERADO:
  Os 3 botões ⤒ / ⊟ / ⤓ no canto superior direito do viewport devem sempre
  estar visíveis e corretamente posicionados — inclusive ao redimensionar a
  janela, ao abrir/fechar o outline ou ao mostrar/ocultar a RéguaErros.

COMPORTAMENTO ATUAL (BUG):
  `posicionar()` é chamado apenas uma vez em `_configurar()`. Após isso,
  nenhum evento de resize ou mudança de layout re-chama `posicionar()`,
  então os botões ficam deslocados ou sobrepostos ao outline/régua.

CAUSA RAIZ:
  __init__.py, método `_configurar()`:
      self._barra_salto = _BarraSalto(self)
      self._barra_salto.posicionar()   ← chamada única, sem reconexão

  Falta override de resizeEvent e chamada em _atualizar_geometria_outline.

ONDE IMPLEMENTAR:
  _EDITOR_/Editor/__init__.py
    → resizeEvent(self, event): adicionar self._barra_salto.posicionar()
    → _atualizar_geometria_outline: adicionar self._barra_salto.posicionar()

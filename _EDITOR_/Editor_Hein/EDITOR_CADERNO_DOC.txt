────────────────────────────────────────────────────────────────────────────────
O QUE É ESSE EDITOR
────────────────────────────────────────────────────────────────────────────────

Esse editor é uma versão INDEPENDENTE do Editor principal da IDE hein,
adaptada para ser um "Editor Caderno" — voltado exclusivamente para arquivos
com extensão .hein.

Não é um editor de código. É um editor de anotações, diário, notas pessoais.
A aparência é de uma folha de caderno pautado.

REGRA DE INDEPENDÊNCIA:
  Qualquer arquivo externo (de fora desta pasta) que precisar de modificação
  para o Editor_Hein deve ser COPIADO para dentro desta pasta e modificado
  aqui. Arquivos externos que não precisem de modificação podem ser importados
  de onde estão com import relativo (..Modulo).

  EXCEÇÃO ACEITA: adicionar apenas uma constante nova em _CONFIGURA_/__init__.py
  é permitido (não altera estrutura do arquivo global). Modificar lógica ou
  estrutura desse arquivo continua proibido.

────────────────────────────────────────────────────────────────────────────────
REGRA PRINCIPAL
────────────────────────────────────────────────────────────────────────────────

  • Só abre arquivos com extensão .hein
  • load_file() retorna False para qualquer outra extensão
  • O mixin_projeto.py roteia automaticamente: arquivos .hein → EditorHein

O QUE ESTÁ FUNCIONANDO HOJE
────────────────────────────────────────────────────────────────────────────────

1. VISUAL CADERNO
   • Fundo claro creme (#FDFBF7 padrão)
   • Texto escuro (#1A1A1A padrão)
   • Pautas horizontais cobrindo toda a largura do editor (gutter + viewport)
   • Pautas cobrem toda a altura, inclusive abaixo do último bloco
   • Linha vermelha vertical na borda esquerda do viewport (margem do caderno, #C0392B)
   • Números de linha na cor da pauta
   • Gutter sempre com a mesma cor do fundo
   • Gutter desenha suas próprias pautas via paintEvent em AreaNumerosLinhaHein
     (mais confiável do que depender só do overlay — ver sessão 3)

2. MENU FLUTUANTE (_FloatHeinMenu)
   • Posicionado no canto superior direito do viewport
   • Exibe a data atual no formato DD/MM/AA
   • Botão ≡ abre painel inline com 3 seletores de cor:
       - Texto  → cor do texto do editor
       - Fundo  → cor do fundo (gutter acompanha automaticamente)
       - Pauta  → cor das linhas horizontais do caderno
   • Cada botão mostra a cor atual como preview colorido
   • Ao confirmar cor, aplica imediatamente via _aplicar_cores_caderno()
     E salva automaticamente em AppData (JSON persistente)
   • Se reposiciona quando o editor é redimensionado
   • Layout: [data] [≡] — sem separador vertical entre eles

3. INTEGRAÇÃO COM mixin_projeto.py
   • Importado como: from _EDITOR_.Editor_Hein import EditorHein
   • EditorHein = CodeEditor (alias no final do __init__.py)
   • Signals obrigatórios declarados:
       - arquivo_salvo     Signal(str)
       - navegar_arquivo   Signal(str, int)
       - erros_atualizados Signal(int)
       - arquivo_exportado Signal(str)  ← stub, nunca dispara
   • arquivo_salvo conectado à statusbar da MainWindow:
       self.statusBar().showMessage(f"Salvo: {nome}", 3000)

4. CORES DO CADERNO — PERSISTÊNCIA
   • _cor_fundo = "#FDFBF7"   (creme)
   • _cor_texto = "#1A1A1A"   (quase preto)
   • _cor_pauta = "#D8D0C8"   (cinza rosado claro)
   • Linha vermelha de margem = "#C0392B" (fixo, não configurável pelo menu)
   • Cores escolhidas pelo menu flutuante são salvas em:
       %APPDATA%/hein/editor_hein_cores.json   (Windows)
       ~/.config/hein/editor_hein_cores.json   (Linux/Mac)
   • Carregadas automaticamente ao abrir qualquer arquivo .hein

5. FOLD / DOBRAMENTO DE BLOCOS
   • Setas de fold aparecem no gutter para qualquer linha de texto .hein
     cujo próximo bloco não-vazio tenha recuo maior (lógica por indentação pura)
   • Clicar na seta → toggle_dobramento() → recolher_bloco() / expandir_bloco()
   • Ctrl+Click → Ctrl+. → comportamentos herdados do mixin
   • Ghost BP decorativo (● cinza claro) aparece no gutter em linhas dobráveis
     (só visual — não é breakpoint real, não interfere com os BPs do debugger)
   • ··· aparece no número de linha quando um bloco está colapsado

6. ATALHOS ESPECÍFICOS DO CADERNO
   • Ctrl+Shift+T  → insere data como título: # Dia, DD de Mês de AAAA
   • F4            → alterna modo leitura (sem gutter, margens largas)
   • Ctrl+Click em [[wikilink]] → navega para o arquivo .hein referenciado
   • Ctrl+S        → salva + exibe "Salvo: nome.hein" na statusbar por 3s

7. REALCE POR ESTRUTURA (HighlighterHein)
   • Linha sem recuo (coluna 0) → NEGRITO + cor COR_TOPICO_PAPEL  → tópico
   • Linha indentada             → normal                          → parágrafo
   • # em qualquer posição       → itálico + cor da pauta (comentário/observação)
   • Tags de alinhamento (miniaturizadas — fonte menor):
       #al:texto  → alinha à esquerda
       #al;texto  → alinha ao centro
       #:texto    → alinha à direita
   • Não realça sintaxe Python — o caderno é texto estruturado por indentação
   • Ativado via _trocar_realce_por_extensao() para ext == '.hein'
   • ATENÇÃO Qt6: peso de fonte deve ser int(QFont.Weight.Bold) = 700
     Usar QFont.Bold diretamente retorna valor Qt5 (75) — fora da escala
     100–900 do Qt6 → negrito não aparece visualmente

8. INDENTAÇÃO VISUAL EM LINHAS QUEBRADAS (wrap_linha = True)
   • Quando wrap_linha está ativo, linhas longas quebram antes do menu flutuante
     (margem direita do viewport = ReguaErros.LARGURA + float_menu.width() + 10 px)
   • Ao quebrar, linhas de continuação mantêm o recuo do bloco original
     (hanging indent via QTextBlockFormat.setLeftMargin + setTextIndent)
   • Número de linha aparece APENAS na primeira sub-linha do bloco visual;
     sub-linhas de continuação ficam em branco no gutter
   • Implementado em _atualizar_indent_bloco_atual() / _aplicar_indent_visual()
     conectados ao sinal textChanged com flag _atualizando_indent para evitar recursão

9. AUTOCOMPLETE FILTRADO (GerenciadorAutocompleteHein)
   • Sem tooltip de assinatura: ao_parentese_aberto() → pass
   • Do Jedi: aceita apenas type == 'function' ou 'class' (funções/classes do usuário)
     Remove: keyword, statement, module, param, instance, auto_import
   • Mantém: word completion (buffer), AppData (palavras/símbolos/emojis),
     file-path completer, snippets
   • Colon ':' como gatilho de emoji/símbolo: mantido (útil para notas)

10. GUIA VERTICAL COL-80 + HARD WRAP
    • _CodeLensOverlay desenha linha pontilhada vertical na coluna 80
      (cor semitransparente da pauta — não intrusiva)
    • Hard wrap automático: ao digitar um caractere na coluna ≥ 80,
      insere quebra de linha preservando o recuo atual do bloco
    • Só ativo em arquivos .hein (_eh_hein())
    • Limite configurado em COLUNA_LIMITE_CADERNO (= 80) em _CONFIGURA_/__init__.py

11. COMPORTAMENTOS DE TECLADO ESPECIAIS (keyPressEvent)
    • Enter após linha de tópico (col-0) sem ':' → insere ':' antes da quebra
      (exemplo: "Reunião" + Enter → "Reunião:\n")
    • ':' no final de linha indentada (sem '▸') → insere prefixo '▸ '
      antes do conteúdo da linha, mantendo o recuo
      (exemplo: "  tarefa:" → "  ▸ tarefa:")

PROBLEMA 1 — LINHAS DUPLAS NO EDITOR
──────────────────────────────────────
  Causa raiz:
    O paintEvent do CodeEditor abria QPainter(self.viewport()) EXTERNAMENTE
    à janela oficial de Paint do viewport. Qt usa double-buffering: pinturas
    fora do evento de Paint vão direto para a tela (não ao backbuffer) →
    artefato visual duplo que some no screenshot.

    Simultaneamente, _CodeLensOverlay (do editor original) interceptava o
    Paint do viewport via eventFilter e chamava QPlainTextEdit.paintEvent()
    (implementação C++, sem as pautas) — criando dois caminhos de renderização
    desalinhados.

    Agravante: _code_lens.py havia sido deletado da pasta Editor_Hein, mas o
    "from ._code_lens import" permanecia em __init__.py → ModuleNotFoundError
    mascarado pelo cache .pyc do arquivo antigo.

  Solução:
    a) Criado novo _code_lens.py DENTRO de Editor_Hein/ (independente do
       original em _EDITOR_/Editor/).
    b) Classe _CodeLensOverlay reescrita: intercepta QEvent.Paint do viewport
       e executa a sequência correta em UMA ÚNICA janela de Paint:
         1. QPlainTextEdit.paintEvent()  → texto + fundo (C++ direto)
         2. _desenhar_pautas()           → linhas horizontais + margem vermelha
         3. _desenhar_cursor()           → cursor personalizado + multi-cursor
    c) paintEvent override REMOVIDO do CodeEditor (__init__.py).
    d) Espaçamento das pautas extra (abaixo do último bloco) corrigido:
       usa int(geo.height()) da geometria real do bloco, não fontMetrics().height()
       — que era diferente da altura real quando havia line-spacing, gerando
       pautas desalinhadas ao rolar o documento.

  Arquivos alterados:
    _EDITOR_/Editor_Hein/_code_lens.py   → criado do zero
    _EDITOR_/Editor_Hein/__init__.py     → paintEvent removido; imports atualizados

PROBLEMA 2 — PAUTAS NÃO PASSAVAM PELO GUTTER
──────────────────────────────────────────────
  Causa raiz:
    As pautas eram desenhadas em self.viewport(), que começa APÓS o gutter.
    AreaNumerosLinha (gutter) é um QWidget filho separado que pinta a si mesmo
    de forma independente — as pautas não o atravessavam.

  Solução:
    Classe _PautaGutterOverlay adicionada em _code_lens.py:
    • Widget filho transparente (WA_TranslucentBackground + WA_TransparentForMouseEvents)
      posicionado sobre area_numeros (o gutter).
    • paintEvent calcula os mesmos y das pautas do viewport (firstVisibleBlock +
      blockBoundingGeometry + dy de alinhamento entre gutter e viewport).
    • Instanciado em _configurar() como self._pauta_gutter_overlay.
    • sync_geometry() chamado em _atualizar_geometria_outline() e via
      resizeEvent (indiretamente pela chamada a _atualizar_geometria_outline).

  Arquivos alterados:
    _EDITOR_/Editor_Hein/_code_lens.py   → classe _PautaGutterOverlay adicionada
    _EDITOR_/Editor_Hein/__init__.py     → instanciação + sync no resize

PROBLEMA 3 — FOLD SEM SETAS NO GUTTER PARA ARQUIVOS .hein
───────────────────────────────────────────────────────────
  Causa raiz:
    AreaNumerosLinha tem método próprio _es_dobravel(texto, extensao) que decide
    se uma linha recebe seta de fold no gutter. Ele cobre:
      .py, .json, .html/.htm/.xml, .yaml/.yml, .js/.ts/.jsx/.tsx/.css/.scss/.less
    .hein NÃO está mapeado → retorna False → zero setas para arquivos .hein.
    (Nota: _linha_e_dobravel() do editor_dobramento.py JÁ funciona corretamente
    para .hein via lógica de indentação pura, mas o gutter não o consultava.)

  Solução:
    Criada subclasse AreaNumerosLinhaHein em _numeros_linha_hein.py:
    • Herda TODO o comportamento de AreaNumerosLinha (pintura, breakpoints,
      bookmarks, git diff, hover, fold arrows) sem nenhuma outra alteração.
    • Sobrescreve apenas _es_dobravel():
        - extensão != '.hein' → delega ao super() (comportamento original)
        - extensão == '.hein' → usa proximo_txt recebido do pai para verificar
          se o próximo bloco não-vazio tem recuo maior (indentação pura)
    • CodeEditor.__init__ passa a instanciar AreaNumerosLinhaHein no lugar
      de AreaNumerosLinha.
    • numeros_linha.py original (só existe como .pyc, sem fonte) NÃO foi
      modificado — a subclasse resolve o problema sem tocar no arquivo externo.

  Arquivos alterados:
    _EDITOR_/Editor_Hein/_numeros_linha_hein.py  → criado do zero
    _EDITOR_/Editor_Hein/__init__.py             → import + instanciação trocada

CORREÇÃO 4 — TEXTO ULTRAPASSANDO O MENU FLUTUANTE (wrap_linha)
───────────────────────────────────────────────────────────────
  Causa raiz:
    QPlainTextEdit.WidgetWidth quebra na largura do viewport. O menu flutuante
    era filho do viewport mas a margem direita não o considerava → texto ia
    até a borda do viewport e ficava embaixo do menu antes de quebrar.

  Solução:
    _atualizar_geometria_outline() agora calcula:
      menu_w = self._float_menu.width() + 10   (após adjustSize())
      right  = ReguaErros.LARGURA + menu_w
      self.setViewportMargins(..., right, ...)
    O viewport fica mais estreito pelo tamanho exato do menu → quebra ocorre
    antes do menu sem criar faixa branca entre o texto e a borda do widget.
    (Nota: a faixa branca visível é o espaço reservado do viewport; as pautas
    do viewport já cobrem esse espaço pois são desenhadas em largura total.)

  Arquivo alterado:
    _EDITOR_/Editor_Hein/__init__.py  → _atualizar_geometria_outline

FUNCIONALIDADE — INDENTAÇÃO VISUAL NAS QUEBRAS (hanging indent)
────────────────────────────────────────────────────────────────
  Problema:
    Com wrap_linha ativo, linhas de continuação (wrap visual) começavam em
    coluna 0 em vez de manter o recuo do bloco — "saía da tab".

  Solução:
    Dois métodos adicionados ao CodeEditor:

    _atualizar_indent_bloco_atual():
      Conectado a textChanged. Lê o bloco atual, mede largura do espaço
      branco inicial (fontMetrics().horizontalAdvance(texto[:n])) e chama
      _aplicar_indent_visual(). Flag _atualizando_indent evita recursão.

    _aplicar_indent_visual(bloco):
      Calcula indent_px = largura dos espaços/tabs iniciais.
      Aplica via QTextBlockFormat:
        setLeftMargin(indent_px)    → toda a linha de continuação começa em X
        setTextIndent(-indent_px)   → primeira linha recua de volta para 0
      Resultado visual:
        • 1ª linha: começa em pixel 0 (espaços/tabs reais visíveis)
        • Linhas de quebra: começam em indent_px (recuo preservado)
      Otimização: verifica se o formato já está correto antes de reescrever
      (evita modificar o documento desnecessariamente).

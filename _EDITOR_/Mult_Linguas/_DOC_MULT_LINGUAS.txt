1. OBJETIVO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Mult_Linguas/ é o sistema de providers de linguagem do editor da hein IDE.
Centraliza, para cada linguagem suportada, cinco responsabilidades:
  1. Realce de sintaxe (qual QSyntaxHighlighter usar)
  2. Outline / preview (qual modo e quais funções de parse chamar)
  3. Dobramento (folding_fn — quais linhas são dobráveis)
  4. Lint (se _ThreadLint deve rodar)
  5. Execução (can_run — se F1/Run deve abrir ExecutorTerminal)

O objetivo é que o Editor.py e o PainelOutline não precisem conhecer a
linguagem diretamente — apenas chamam get_provider(ext) e delegam ao provider.

Localização: hein/_EDITOR_/Mult_Linguas/

2.1 LanguageManager (Mult_Linguas/__init__.py)
  - Registro central: dict {'.ext': provider_instance}.
  - _descobrir(): ao importar o módulo, percorre subpastas (exceto Base/ e
    __pycache__), importa cada __init__.py e captura o atributo LANGUAGE_PROVIDER.
    Usa duck-typing (hasattr 'extensions' + 'outline_mode') em vez de isinstance
    para evitar falha silenciosa em namespace packages.
  - get_provider(ext): normaliza a extensão (aceita '.py', 'py' ou caminho
    completo); retorna o provider registrado ou PythonProvider como padrão.
  - register(provider): registro manual para providers externos.
  - is_registered(ext): usado por editor_dobramento para distinguir extensões
    conhecidas de desconhecidas.

2.2 LanguageProvider (Base/provider.py)
  - Classe base com todos os atributos e métodos com valores padrão seguros.
  - Atributos obrigatórios que cada provider define:
      extensions      list[str]   ex: ['.py', '.pyw']
      name            str         ex: 'Python'
      outline_mode    str         ver tabela de modos abaixo
      lint            bool        True → _ThreadLint roda
      autocomplete    str         'jedi' | 'none'
      spell_check     bool        True → CorretorOrtografico instanciado para
                                  o arquivo; clique do meio e menu de contexto
                                  ativam verificação ortográfica PT-BR
  - Atributos de execução:
      can_run         bool        True → F1 abre ExecutorTerminal (não-Python)
      run_extensoes   list[str]   subset executável; [] = usa extensions inteiras
  - Atributos para a barra inferior do PainelOutline:
      status_rotulo_a   rótulo do 1.º label de contexto (ex: 'Classe')
      status_rotulo_b   rótulo do 2.º label de contexto (ex: 'Função')
      mostrar_erros     True → _lbl_ol_erros visível
      rotulo_erros      'Erros' | 'Válido' | ''
  - Métodos sobrescreváveis:
      create_highlighter(document) → QSyntaxHighlighter
          retorna o highlighter para o documento; padrão: _RealceInerte
      folding_fn(texto, ext) → bool
          retorna True se a linha é dobrável; padrão: False (nenhuma linha)
      provide_outline(codigo, callback)
          ASSÍNCRONO — inicia parse e chama callback(itens) ao concluir;
          padrão: callback([]) (outline vazio)

2.3 _RealceInerte (Base/provider.py)
  - QSyntaxHighlighter que não aplica nenhuma cor — highlightBlock() é noop.
  - Usado como padrão em create_highlighter() da base.
  - Providers em fase inicial que ainda não têm realce real
    (ex: Lua) NÃO sobrescrevem create_highlighter() — herdam a base.

2.6 Módulos de implementação por subpasta

  Python/
    realce.py     — RealceSintaxePython (QSyntaxHighlighter)
                    keywords, built-ins, def/class, decoradores, strings simples/
                    f-string/multilinhas (estado de bloco), comentários.
                    Lê cores do dicionário de tema via aplicar_tema().
                    Tags de Comentário hein (paleta fixa, independente de tema):
                      #cod:  "título" — pinta o FUNDO do comentário e fica
                             ATIVO em modo FUNDO (cod = 1ª+última letra do
                             nome da cor: al=azul, vo=vermelho, po=preto,
                             ao=amarelo, ca=cinza, co=ciano, ba=branca,
                             ve=verde, ra=rosa, ro=roxo, mm=marrom, la=laranja).
                      #cod;  "parágrafo"/referência pontual — pinta só a
                             FONTE, em qualquer parte do arquivo, e fica
                             ATIVO em modo FONTE.
                      #:     herda o TIPO (fundo ou fonte) e a COR de quem
                             estiver mais próximo acima — seja um #cod: ou
                             um #cod; — sem redigitar o código.
                    Estado combinado no block state do Qt: unidade = estado
                    tríplice de string multilinha (0/1/2), dezena+ = índice
                    da tag ativa (0 = nenhuma; 1..N = modo fundo; N+1..2N =
                    modo fonte, N = _N_TAGS_COMENTARIO). Ver
                    _PALETA_TAGS_COMENTARIO no topo do arquivo.
                    Minimizar código da tag: o texto do marcador (#al:, #al;,
                    #:) aparece discreto por padrão (fonte pequena/apagada,
                    formato self._formato_tag_mini) e só volta ao tamanho
                    normal na linha onde está o cursor ou dentro de uma
                    seleção. Estado rastreado em _linha_cursor_tag /
                    _bloco_selecao_inicio / _bloco_selecao_fim, atualizado via
                    definir_linha_cursor_tag() e definir_selecao_tag() —
                    chamados pelo CodeEditor (ver _EDITOR_/Editor/__init__.py)
                    a partir de cursorPositionChanged/selectionChanged, com
                    hasattr() porque _realce troca de classe por extensão de
                    arquivo (só RealceSintaxePython tem esses métodos).
                    Color preview / swatch: qualquer literal hex #RRGGBB ou
                    #RGB no código (regex _re_cor_hex) ganha fundo com a
                    própria cor e fonte preta/branca escolhida por contraste
                    de luminância — formato calculado sob demanda e
                    cacheado em _cache_formato_hex (não é fixo como a
                    paleta das Tags de Comentário).
    lint.py       — _ThreadLint (QThread)
                    Roda pyflakes/flake8 em background com debounce;
                    emite erros(dict) para ReguaErros e calha.
    validador.py  — ValidadorImports + _ThreadValidador
                    Detecta imports inválidos em thread background.

4.1 Auto-descoberta na importação
  ──────────────────────────────────────────────────────────────────────────
  import _EDITOR_.Mult_Linguas
    → _descobrir() executado
    → itera subpastas (exceto Base/, __pycache__)
    → importlib.import_module('_EDITOR_.Mult_Linguas.<Subpasta>')
    → getattr(mod, 'LANGUAGE_PROVIDER', None)
    → duck-typing: hasattr(p, 'extensions') and hasattr(p, 'outline_mode')
    → _registro['.ext'] = provider  (para cada ext em provider.extensions)
    → subpasta == 'Python' → _provider_padrao = provider
    → falha de importação → log.aviso() silencioso (nunca trava a IDE)
  ──────────────────────────────────────────────────────────────────────────

4.2 Abertura de arquivo no Editor
  ──────────────────────────────────────────────────────────────────────────
  Editor.abrir_arquivo(caminho)
    → ext = os.path.splitext(caminho)[1]
    → provider = get_provider(ext)
    → highlighter = provider.create_highlighter(document)
    → if provider.lint: _ThreadLint.iniciar()
    → if provider.autocomplete == 'jedi': GerenciadorAutocomplete.ativar()
  ──────────────────────────────────────────────────────────────────────────

4.3 Atualização do Outline
  ──────────────────────────────────────────────────────────────────────────
  PainelOutline._atualizar()
    → provider = get_provider(ext_do_arquivo_ativo)
    → despacha por provider.outline_mode:
        'python_ast'   → _ThreadOutlinePy.start() → _popular_arvore_python()
        'tree_json'    → _analisar_json()   (→ JSON/outline.py)
        'tree_xml'     → _analisar_xml()    (→ XML/outline.py)

6. REGRAS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  RM-01  Cada subpasta DEVE expor LANGUAGE_PROVIDER = <Classe>Provider().
         O LanguageManager só lê esse atributo — nunca instancia classes
         diretamente.

  RM-02  Duck-typing obrigatório em _descobrir() — nunca usar isinstance().
         Razão: namespace packages sem __init__.py podem carregar a mesma
         classe por dois caminhos distintos, fazendo isinstance retornar False
         mesmo para uma instância válida.

  RM-03  create_highlighter() e folding_fn() NUNCA bloqueiam a UI thread.
         Parse pesado (AST, xml.etree) vai em provide_outline() com callback.

  RM-04  Cores de realce SEMPRE via tema_global().dados() — nunca hex
         hardcoded dentro dos módulos de Mult_Linguas/.

  RM-05  Shims em Funcionalidades/ são temporários. Não remover até confirmar
         que nenhum módulo externo a Mult_Linguas/ importa de
         Funcionalidades/realce_*.py ou validador_imports.py.

  RM-06  Adicionar nova linguagem = criar subpasta + __init__.py com
         LANGUAGE_PROVIDER. Nenhuma alteração necessária em __init__.py do
         LanguageManager — a descoberta é automática.

  RM-07  Provider com can_run=True e run_extensoes=[] executa TODAS as
         extensões do provider. Use run_extensoes para restringir
         (ex: JavaScript executa .js/.jsx/.ts/.tsx, mas não .css/.scss).

  RM-08  F1/Run em provider com can_run=False deve retornar silenciosamente
         (return sem ação) — nunca exibir erro ou abrir terminal Python.

  RM-09  Providers em fase inicial sem realce real NÃO sobrescrevem
         create_highlighter() — herdam _RealceInerte da base.
         NUNCA usar _RealceInerte sem importá-lo explicitamente se o método
         for sobrescrito na subclasse.

7. OBSERVAÇÕES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  - O bug de registro de providers JSON e HTML (causava outline vazio /
    "Linha 1: Sintaxe Inválida") foi provocado por isinstance() verificando
    contra LanguageProvider importado por dois caminhos distintos.
    A solução (duck-typing com hasattr) foi implementada em _descobrir().

  - PythonProvider é o provider padrão para extensões não registradas.
    Arquivo .xyz desconhecido receberá realce Python — intencional.

  - Bug histórico (2026-07-08): JavaScript/__init__.py, C_CPP/__init__.py e
    Makefile/__init__.py foram gerados com strings de regex não fechadas
    (SyntaxError), impedindo o _descobrir() de registrar os três providers.
    Corrigidos reescrevendo os arquivos com regex corretas (_RE_*_FOLD).

  - Bug histórico (2026-07-08): Lua/__init__.py sobrescrevia create_highlighter()
    usando _RealceInerte sem importá-lo (NameError em runtime).
    Corrigido removendo o override — herda da base.

  - Bare filenames sem extensão ('Makefile', 'GNUmakefile', 'Dockerfile'):
    não são reconhecidos pelo get_provider() (que normaliza por extensão).
    Futuro: matching por basename no LanguageManager.

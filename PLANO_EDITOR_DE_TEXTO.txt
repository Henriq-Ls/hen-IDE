PLANO DO PROJETO: EDITOR DE TEXTO DESKTOP HEN-DITOR
===================================================

Este arquivo é o handoff do projeto. Ele deve ser lido antes de qualquer
alteração por outra IA ou por outra pessoa.

OBJETIVO
--------

Transformar o hen-Ditor em um editor de texto desktop feito em PySide6, com uma
experiência visual semelhante à de uma IDE, mas sem tentar manter uma IDE
completa.

O editor de texto, a edição e o autocomplete são o núcleo do produto. Não criar
um aplicativo web e não trocar o projeto por uma implementação web.

LAYOUT OBRIGATÓRIO
------------------

Manter estas quatro áreas na janela principal:

1. File Tree à esquerda;
2. editor com abas no centro;
3. painel de IA à direita;
4. terminal na parte inferior.

Essas áreas devem continuar funcionando juntas. Não entregar apenas uma tela
estática ou um editor isolado.

DECISÕES DE PRODUTO JÁ TOMADAS
------------------------------

- O `Editor_Hein` trabalha exclusivamente com arquivos `.hen`.
- Arquivos `.txt`, `.md`, `.py`, `.js`, `.ts`, `.json`, `.html`, `.css`, `.csv`
  e qualquer outra extensão devem ser recusados claramente; não criar um
  segundo editor para essas extensões.
- Preservar o editor `Editor_Hein.CodeEditor`, pois ele é a referência do
  cérebro do produto.
- Preservar autocomplete, edição, busca, múltiplos cursores, gutter,
  realce por extensão e salvamento quando esses recursos já estiverem
  funcionando no `Editor_Hein`.
- Preservar File Tree, painel de IA, terminal e os utilitários de
  `_UTILITARIOS_`.
- Manter Git local, se possível por ações locais e status/diff, mas não incluir
  login, push, pull ou criação de repositório no GitHub.
- Não alterar o terminal nesta etapa. Reutilizar `TerminalTabWidget` como ele
  está e só conectar a janela a ele.
- Preservar os recursos de log necessários ao editor. O painel visual antigo de
  logs não é prioridade.
- O `_NUCLEO_` ainda precisa de uma auditoria profunda em etapa futura. Não
  fazer uma remoção ampla dessa pasta como atalho.

IMPLEMENTAÇÃO RECOMENDADA
--------------------------

### 1. Conferir antes de editar

- Ler `replit.md`, se existir, e conferir as instruções atuais do projeto.
- Conferir os arquivos e imports presentes no diretório; não confiar em
  afirmações antigas deste plano.
- Usar busca de imports e referências para descobrir dependências reais.
- Confirmar que a janela antiga instancia GitHub antes de reutilizar qualquer
  composição.

### 2. Criar uma composição desktop enxuta

Criar uma janela principal nova em um módulo próprio dentro de `_APP_`, sem
usar diretamente todos os mixins da IDE antiga.

Essa janela deve importar diretamente, depois de conferir os caminhos reais:

- `PainelArquivos`;
- `TabWidget`;
- `Editor_Hein.CodeEditor`, por meio do `TabWidget`;
- `PainelIA`;
- `TerminalTabWidget`.

Montar a janela com `QSplitter` ou composição equivalente:

- File Tree à esquerda;
- abas/editor no centro;
- IA à direita;
- terminal embaixo.

Não instanciar `PainelGitHub`, `MainWindow` antiga, tarefas, debugger,
executores ou componentes de IDE que não sejam necessários para o editor.

### 3. Corrigir a integração das abas e do editor

- Alterar `tab_widget.py` para usar `Editor_Hein.CodeEditor`.
- Fazer a abertura de arquivo da árvore chegar às abas do editor.
- Preservar o comportamento de preview em clique simples, se os sinais atuais
  permitirem isso, e abertura definitiva em duplo clique ou ação explícita.
- Garantir que abas modificadas, salvar, salvar como e fechar funcionem.
- Restringir `CodeEditor.load_file`, `save_file`, `TabWidget` e File Tree a
  `.hen`, recusando outras extensões de forma explícita.
- O filtro de `save_file` deve oferecer somente `.hen` e salvar diretamente no
  caminho já associado à aba.

### 4. Conectar IA e terminal

- Usar `PainelIA.set_editor`, `set_terminal_widget`, `set_nucleo` e
  `set_projeto` somente depois de conferir as assinaturas e dependências.
- Se a IA puder funcionar sem o `_NUCLEO_`, deixá-la desacoplada nesta primeira
  composição; não criar uma conexão falsa.
- Ligar o editor atual ao painel de IA.
- Reutilizar `TerminalTabWidget` sem refatorar o terminal nesta etapa.
- A execução de arquivo, se for mantida, deve abrir/usar o terminal existente,
  não criar um segundo mecanismo de execução.

### 5. Inicialização

- Fazer `_APP_/__init__.py` ser o ponto de inicialização da aplicação desktop.
- Simplificar `hen-Ditor/main.py` para delegar a inicialização ao `_APP_`.
- Preservar somente a preparação de ambiente, logs, AppData e lock que ainda
  forem necessários.
- Não reintroduzir a antiga `MainWindow` como requisito da nova janela.

### 6. Git local

Manter somente operações locais e seguras no projeto, por exemplo status,
diff, adicionar arquivos e commit local, se já houver suporte aproveitável.

Não montar painel de GitHub e não manter ações de login, push, pull ou criação
de repositório remoto. Qualquer ação destrutiva ou commit deve ser claramente
identificado na interface.

POLÍTICA DE LIMPEZA
-------------------

A limpeza só pode acontecer depois que a nova composição iniciar e os recursos
necessários forem verificados.

Pode ser removido individualmente, após rastrear imports, sinais e callbacks:

- módulos de threads que não forem mais usados;
- debugger/DAP;
- tarefas;
- executores;
- componentes antigos de busca/configuração da IDE;
- painel GitHub;
- duplicações antigas do editor;
- módulos de log visual que não forem dependência do editor, IA ou terminal.

Não apagar uma pasta inteira por nome. Em especial, não apagar antes de
rastrear:

- `_EDITOR_`;
- `_APP_`;
- `_LOG_`;
- `_THREADS_`;
- `_UTILITARIOS_`;
- `_NUCLEO_`;
- `_TERMINAIS_`.

O terminal não deve ser removido nem alterado nesta etapa. O `_UTILITARIOS_`
deve ser preservado conforme a decisão do usuário. Só remover um utilitário
quando a busca confirmar que não é usado por nenhuma parte mantida.
